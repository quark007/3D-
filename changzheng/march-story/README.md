# 剧情与小游戏整合（B方 · 本地版）

当前入口是项目根目录 `index.html`；不是归档副本。默认章节入口在真实 A 方模块就绪后进入立体场景，角色行走与碰撞全部由 `march-world/` 提供。本目录不含替代渲染器或占位场景。

## 运行

在 `E:\新建文件夹\changzheng` 执行：

```powershell
node tools/build_web31.cjs
python -m http.server 8141
```

打开 `http://127.0.0.1:8141/`，选岗位，沿原序章进入征程，选择章节后走近 NPC 或任务点。键盘 WASD/方向键移动，E 确认交互；手机使用 A 方的触控移动与交互按钮。头部可返回路线图；底部给出当前准备事项和寻找方向。

构建会按当前源码生成注册表、A/B 映射、内容指纹、合并包和 SW；无需安装前端框架。独立解谜页的本地回传脚本也随构建更新指纹与缓存。

## 内容与接入策略

- 十二个原始章 ID 保留，包含吴起镇之后的三大主力会师。
- 注册表来自当前 `GAME_NODES`、72份原 NPC 剧本、四岗位参与者、OptionalLab71、StarfireBook73、英雄支线、章节任务与独立解谜页。详见 `inventory.json`、`INTEGRATION-TABLE.md`。
- 固定对白调用真实 `NpcDialogueFlow.options/choose/undo` 与 `NpcStoryCore`；首章必要3轮，其余沿用真实规则。未完成本章协作时，不提前开放收尾片段。
- 第一章保留原 `JourneyChapter` 六阶段完整任务：整装、岗位协作、行动计划、途中互助、六段渡河、行记复盘。使用真实操作及新增可选完成回调，成功可替代本章简短协作，不直接跳到下一章。原单参数入口行为保留。
- 草地另提供原队员资料、份额规则与 `calcRationResult` 评价支持的分粮面板；可调整、保存草稿及刷新恢复。沿用 `rationRecords` 字段记录方案，新场景不执行原战斗减员效果。
- 可选支线完成不直接完成章节。原射击、攻击或减员循环在新场景入口改用观察择路、运输调度、检查铺板、资料归档或节奏协作；保留原剧情目的与来源映射，不调用 Run 的全局门禁旁路。
- 其余适用小游戏通过真实旧签名启动。原生无参数成功回调仅允许已核对的引擎白名单；结果对象必须明确 `won:true` 或 `win:true`。关闭、超时、异常都不当成功。
- 七个本地独立解谜页单独登记，不把它们当作全量剧情。iframe 完成需同时通过 origin、contentWindow、会话 nonce、具体成功信号校验；旧档案页不带会话时仍收到原字符串信号。
- `mystery/index.html` 未被当前主入口引用，是独立原型；没有把它的另一套存档或关闭后兜底发奖逻辑导入本游戏。未使用或虚构任何短链接，也未把截断原型当成可运行模块。

## 存档与回传

场景进度在原 `GameState.storyPreparations.marchStory83` 内保存，沿用 schemaVersion 3 和 PlayerProfiles40 的玩家分域。原完整第一章在相同 GameState 的 `journey83_1` 中存阶段，`journey83_history` 保留最近10次方案记录；新场景模式不新建旧 `changzheng_journey_v1` 存储键。原对话分域键、各小游戏已有成绩/阶段键继续使用，未新建平行的主存档。

保存内容包含各场景位置、当前章、任务检查点、有限次尝试记录、协作中间安排、已完成章节及今日行程目标。旧勋章支持的完成进度迁入，未据旧分数推断可选小游戏胜利。按勋章同步章节解锁，兼容旧档非连续完成记录。

对话/小游戏前保存 `world.snapshot()`，按原因暂停，结束后恢复同一位置。刷新中断记为 interrupted，不发完成奖励；保留已经保存的准备进度。**没有声称所有旧引擎都能逐帧续局**：原引擎有阶段存档的继续沿用，没有局内序列化接口的回到原位置后重开练习。不会用直接替换私有闭包状态伪造恢复。

保存失败会回滚新记录并显示提示。回调按会话与玩家校验；同一玩家清档、导入另一存档或切换岗位，也会废弃旧回调，pagehide 不会把清掉的旧场景重新写回。完成标记幂等，旧主线战斗分不被新的协作结算覆盖。

完整第一章的原队伍资源结算只执行一次；已有第一章勋章也防止重领。重玩保留不同方案与决策记录，不重复改变共享资源；新场景不会把其成绩写入旧战斗评分。原分粮方案与 B 方完成标记各自保存成功后才返回，取消不确认分配。

## A/B协议与空间映射

六个 `CZMarchWorld` 方法及 `czmarch:interact` 字段保持原约定。`CZMarchStory.boot({container,world})` 可直接使用实际 `CZMarchWorldManifest`；额外可选参数 `sceneManifest` 用于显式映射，不改 A 的函数签名。

`world-bindings.js`、`anchor-requests.json`、`competition/march-story83-world-mapping.json` 给出完整对应关系。按当前 A 方交付重新计算地面净空、可达区域和有效交接点，原说话人、对白、任务 ID 保持。当前3处条目共用 A 已登记的可达交接点，出生点无需覆盖；后续数字随重建重新生成。B 方未修改 A 的渲染、行走、地形或锚点坐标。

今日行程与星火档案共用地点，年报与会师史实资料共用地点；同点会显示可选事项列表。未知锚点明确诊断，不记成功。A 若修改场景，重建会重新核对映射及地面元数据，不沿用猜测坐标。

完整第一章、原分粮面板分别与第1、第9章既有协作点共址。接口桩仅用于单元契约测试，实际入口和浏览器验收使用 A 方十二章交付模块。
